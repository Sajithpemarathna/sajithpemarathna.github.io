Customer Journey and Revenue Analytics on Databricks

Databricks, PySpark, Spark SQL, Delta Lake

A lakehouse pipeline that moves more than 3M raw e-commerce event records through landing, bronze, silver and gold layers and publishes daily funnel and product metrics to the reporting layer. It is built to be re-run rather than run once: every stage is parameterised by run date, silver deduplicates through Delta MERGE so reprocessing a day is idempotent, and a monitoring table logs rows processed per layer and execution status for every run.

  • Revenue follows a sharp Pareto curve.The top 20% of products generate close to 80% of revenue, which is what makes product-level daily tracking worth the pipeline cost and tells merchandising where to concentrate.
  • Designed for reprocessing, not just for running.Bronze appends only the given run date with ingestion metadata attached, silver deduplicates through Delta MERGE, and a single Databricks Job chains the work on serverless compute. Backfilling a bad day is a parameter change rather than a rebuild.
How it is built Bronze appends raw events for one run date with run date, ingestion timestamp and batch id attached. Silver normalises categorical fields, filters invalid records and deduplicates through Delta MERGE. Gold produces two tables: daily funnel KPIs across events, users, sessions, views, carts, purchases, revenue and conversion rate, plus product-level daily performance. A monitoring notebook writes a central run log, and the daily runner orchestrates the chain as a single entry point for scheduled execution and manual backfills.
